## 1. Módulo: Environment (Ambientes)

### 1.1 Registrar Ambiente

**Endpoint**

```
POST /api/admin/environments
```

**Headers**

```
Authorization: Bearer TOKEN
Content-Type: application/json
```

**JSON**

```json
{
  "environmentName": "Ambiente 101",
  "capacity": 30,
  "status": "ACTIVE"
}
```

**Respuesta esperada**

HTTP STATUS

```
201 CREATED
```

Response

```json
{
  "idEnvironment": "8f97e3d2-7b5a-4c1f-a9d8-2c0c2d38d6a7",
  "environmentName": "Ambiente 101",
  "capacity": 30,
  "status": "ACTIVE"
}
```

## 2. Módulo: Eliminación Permanente de Ambientes

### BASE URL

```text
http://localhost:8080
```

### 2.1 Flujo de eliminación permanente de un ambiente

> **Importante:** Un ambiente solo puede eliminarse permanentemente si previamente fue inactivado.

---

### 2.2 Inactivar Ambiente

**Endpoint**

```http
DELETE /api/admin/environments/{UUID_DEL_AMBIENTE}
```

**Headers**

```text
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

**Respuesta esperada**

HTTP STATUS

```text
204 NO CONTENT
```

Sin body.

> Después de esta operación el ambiente queda con estado **INACTIVE**.

---

### 2.3 Eliminar Permanentemente el Ambiente

**Endpoint**

```http
DELETE /api/admin/environments/{UUID_DEL_AMBIENTE}/permanent
```

**Headers**

```text
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

**Respuesta esperada**

HTTP STATUS

```text
204 NO CONTENT
```

Sin body.

> El ambiente es eliminado definitivamente de la base de datos y ya no podrá recuperarse.

---

### 2.4 Validaciones para probar

| Caso | Respuesta esperada |
|------|--------------------|
| Ambiente aún activo | `"El ambiente debe estar inactivo antes de eliminarse permanentemente"` |
| Ambiente inexistente | `"Ambiente no encontrado"` |
| Ambiente asociado a registros | `"No es posible eliminar el ambiente porque tiene registros asociados"` *(si aplica en tu lógica de negocio)* |
| UUID inválido | `400 Bad Request` |
| Sin token | `403 Forbidden` |
| Token de INSTRUCTOR | `403 Forbidden` |

---

### 2.5 Flujo de prueba

**Paso 1 - Inactivar ambiente**

```http
DELETE http://localhost:8080/api/admin/environments/{UUID_DEL_AMBIENTE}
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

Resultado esperado

```text
204 NO CONTENT
```

Estado del ambiente:

```text
INACTIVE
```

**Paso 2 - Eliminar permanentemente**

```http
DELETE http://localhost:8080/api/admin/environments/{UUID_DEL_AMBIENTE}/permanent
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

Resultado esperado

```text
204 NO CONTENT
```

Resultado:

```text
El ambiente fue eliminado permanentemente de la base de datos.
```

## 3. Módulo: Chip Environment (Asignación de Fichas a Ambientes)

### BASE URL

```
http://localhost:8080
```

### 3.1 Asignar Ficha a un Ambiente

**Endpoint**

```
POST /api/admin/chip-environments
```

**Headers**

```
Authorization: Bearer TOKEN
Content-Type: application/json
```

**JSON**

```json
{
  "idChip": "UUID_DE_LA_FICHA",
  "idEnvironment": "UUID_DEL_AMBIENTE",
  "assignmentDate": "2026-07-07"
}
```

**Respuesta esperada**

HTTP STATUS

```
201 CREATED
```

Response

```json
{
  "idChipEnvironment": "uuid-generado",
  "idChip": "uuid-de-la-ficha",
  "chipName": "Ficha ADSO 2025",
  "idEnvironment": "uuid-del-ambiente",
  "environmentName": "Ambiente 101",
  "assignmentDate": "2026-07-07",
  "status": "ACTIVE",
  "message": "Ficha asignada al ambiente correctamente"
}
```

---

### 3.2 Intentar Asignar la Misma Ficha al Mismo Ambiente

**Endpoint**

```
POST /api/admin/chip-environments
```

**Headers**

```
Authorization: Bearer TOKEN
Content-Type: application/json
```

**JSON**

```json
{
  "idChip": "UUID_DE_LA_MISMA_FICHA",
  "idEnvironment": "UUID_DEL_MISMO_AMBIENTE",
  "assignmentDate": "2026-07-07"
}
```

**Respuesta esperada**

HTTP STATUS

```
409 CONFLICT
```

Response

```json
{
  "message": "Esta ficha ya está asignada a ese ambiente"
}
```

---

### 3.5 Eliminar una Asignación (Eliminación Lógica)

**Endpoint**

```
DELETE /api/admin/chip-environments/{UUID_DE_LA_ASIGNACION}
```

**Headers**

```
Authorization: Bearer TOKEN
```

**Respuesta esperada**

HTTP STATUS

```
204 NO CONTENT
```

Response

```
Sin contenido (No Content)
```

**Validaciones**

Si la asignación no existe

```json
{
  "message": "Asignacion no encontrada"
}
```

Si la asignación ya está inactiva

```json
{
  "message": "La asignacion ya está inactiva"
}
```

---

### 3.6 Validaciones Generales

**3.6.1 Ficha inexistente**

Resultado esperado

```json
{
  "message": "Ficha no encontrada"
}
```

**3.6.2 Ambiente inexistente**

Resultado esperado

```json
{
  "message": "Ambiente no encontrado"
}
```

**3.6.3 Asignación duplicada**

Resultado esperado

```json
{
  "message": "Esta ficha ya está asignada a ese ambiente"
}
```

**3.6.4 Campos vacíos**

HTTP STATUS

```
400 BAD REQUEST
```

Resultado esperado

```json
{
  "message": "Los campos obligatorios son requeridos"
}
```

*(El mensaje puede variar según las validaciones implementadas.)*

**3.6.5 Sin token**

HTTP STATUS

```
403 FORBIDDEN
```

Resultado esperado

```json
{
  "message": "Access Denied"
}
```

**3.6.6 Token de INSTRUCTOR**

HTTP STATUS

```
403 FORBIDDEN
```

Resultado esperado

```json
{
  "message": "Access Denied"
}
```

### 3.7 Eliminar Permanentemente una Asignación

**Endpoint**

```http
DELETE /api/admin/chip-environments/{UUID_DE_LA_ASIGNACION}/permanent
```

**Respuesta esperada:** `204 NO CONTENT`

### Validaciones

**Asignación en estado ACTIVE**

Resultado esperado:

```json
{
  "message": "La asignación debe estar inactiva antes de eliminarse permanentemente"
}
```

**Asignación inexistente**

Resultado esperado:

```json
{
  "message": "Asignacion no encontrada"
}
```

### Flujo de prueba

**1. Inactivar la asignación**

```http
DELETE /api/admin/chip-environments/{UUID_DE_LA_ASIGNACION}
```

**Respuesta esperada:** `204 NO CONTENT`

**2. Eliminar permanentemente la asignación**

```http
DELETE /api/admin/chip-environments/{UUID_DE_LA_ASIGNACION}/permanent
```

**Respuesta esperada:** `204 NO CONTENT`

**Resultado:** La asignación queda eliminada definitivamente de la base de datos.
