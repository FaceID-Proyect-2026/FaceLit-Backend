## 1. Módulo: Gestión de Horarios

*(sin cambios respecto a tu versión original — se conserva igual)*

### 1.1 Registrar Horario

**Endpoint**

```http
POST /api/admin/schedules
```

**Headers**

```text
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
Content-Type: application/json
```

**JSON**

```json
{
  "idChip": "UUID_DE_LA_FICHA",
  "idEnvironment": "UUID_DEL_AMBIENTE",
  "idInstructor": "UUID_DEL_INSTRUCTOR",
  "dayOfWeek": "LUNES",
  "startTime": "08:00:00",
  "endTime": "10:00:00"
}
```

**Respuesta esperada**

HTTP STATUS

```text
201 CREATED
```

Response

```json
{
  "idSchedule": "uuid-generado",
  "chipName": "Ficha ADSO 2025",
  "environmentName": "Ambiente 101",
  "instructorName": "Carlos Gomez",
  "dayOfWeek": "LUNES",
  "startTime": "08:00:00",
  "endTime": "10:00:00",
  "status": "ACTIVE",
  "message": "Horario registrado correctamente"
}
```

**Endpoint**

```http
DELETE /api/admin/schedules/{UUID_DEL_HORARIO}
```

**Headers**

```text
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

**Respuesta esperada**

HTTP STATUS

```text
204 NO CONTENT
```

Sin body.

> Después de esta operación el horario queda con estado **INACTIVE**.

---

### 2.3 Eliminar Permanentemente el Horario

> **Importante:** El horario debe estar previamente inactivo.

**Endpoint**

```http
DELETE /api/admin/schedules/{UUID_DEL_HORARIO}/permanent
```

**Headers**

```text
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

**Respuesta esperada**

HTTP STATUS

```text
204 NO CONTENT
```

Sin body.

> El horario es eliminado definitivamente de la base de datos.

---

### 2.4 Validaciones para Probar

| Caso | Respuesta esperada |
|------|--------------------|
| Eliminar permanentemente un horario con estado ACTIVE | `"El horario debe estar inactivo antes de eliminarse permanentemente"` |
| UUID de horario inexistente | `"Horario no encontrado"` |
| Usuario inexistente en la búsqueda | `"Usuario no encontrado"` |
| Aprendiz sin ficha activa | `"No hay horarios disponibles para este usuario"` |
| UUID inválido | `400 Bad Request` |
| Sin token | `403 Forbidden` |
| Token de INSTRUCTOR | `403 Forbidden` |

---

### 2.5 Flujo de Prueba

**Paso 1 - Consultar horario del aprendiz**

```http
GET http://localhost:8080/api/admin/schedules/user/{UUID_DEL_APRENDIZ}
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

Resultado esperado

```text
200 OK
```

Se obtiene el listado de horarios asociados al aprendiz.

**Paso 2 - Inactivar horario**

```http
DELETE http://localhost:8080/api/admin/schedules/{UUID_DEL_HORARIO}
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

Resultado esperado

```text
204 NO CONTENT
```

Estado:

```text
INACTIVE
```

**Paso 3 - Eliminar permanentemente**

```http
DELETE http://localhost:8080/api/admin/schedules/{UUID_DEL_HORARIO}/permanent
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

Resultado esperado

```text
204 NO CONTENT
```

Resultado:

```text
El horario fue eliminado permanentemente de la base de datos.
```

## 4. Módulo: Excepciones de Horario (Schedule Exceptions)

> **Actualizado — RF-4.4 v3.0.** Ahora existen dos tipos de excepción: `ENVIRONMENT_CHANGE` (cambio de ambiente, el caso original) e `INSTRUCTOR_CHANGE` (cambio de instructor, nuevo). Además, la excepción ahora acepta un rango de fechas (`exceptionDate` + `endDate` opcional) en vez de un solo día.
>
> **Importante:** con el fix de `GlobalExceptionHandler`, los errores de este módulo ahora responden `400 Bad Request` con el mensaje real, en vez de `500 Internal Server Error` genérico.

### BASE URL

```text
http://localhost:8080
```

---

### 4.5 Validaciones para Probar

**Comunes a ambos tipos**

| Caso | Respuesta esperada |
|------|--------------------|
| Horario inexistente | `"Horario no encontrado"` |
| `endDate` anterior a `exceptionDate` | `"La fecha de fin no puede ser anterior a la fecha de inicio."` |
| Ya existe una excepción activa que se solapa con el rango de fechas | `"Ya existe una excepción registrada para este horario en la fecha seleccionada."` |
| Excepción ya inactiva (al eliminar) | `"La excepcion ya está inactiva"` |
| UUID de excepción inexistente | `"Excepcion no encontrada"` |
| Fecha con formato inválido | `400 Bad Request` |
| Sin token | `403 Forbidden` |
| Token de INSTRUCTOR | `403 Forbidden` |

**Solo para `ENVIRONMENT_CHANGE`**

| Caso | Respuesta esperada |
|------|--------------------|
| `idEnvironment` no enviado | `"Debe seleccionar un ambiente alterno para este tipo de excepción."` |
| Ambiente alterno inexistente | `"Ambiente no encontrado"` |
| Ambiente alterno igual al original | `"El ambiente alterno debe ser diferente al ambiente original del horario."` |
| Ambiente alterno ocupado en esa franja | `"El ambiente ya está asignado para esa franja horaria."` |

**Solo para `INSTRUCTOR_CHANGE`**

| Caso | Respuesta esperada |
|------|--------------------|
| `idInstructorReplacement` no enviado | `"Debe seleccionar un instructor de reemplazo para este tipo de excepción."` |
| Usuario de reemplazo inexistente | `"El usuario seleccionado no tiene rol de Instructor."` |
| Usuario de reemplazo sin rol `INSTRUCTOR` | `"El usuario seleccionado no tiene rol de Instructor."` |
| Instructor de reemplazo ocupado en esa franja | `"El instructor ya tiene una asignación para esa franja horaria."` |

---

### 4.6 Flujo de Prueba

**Paso 1 - Registrar excepción de ambiente**

```http
POST http://localhost:8080/api/admin/schedule-exceptions
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
Content-Type: application/json

{
  "idSchedule": "{UUID_DEL_HORARIO}",
  "exceptionType": "ENVIRONMENT_CHANGE",
  "idEnvironment": "{UUID_AMBIENTE_ALTERNO}",
  "exceptionDate": "2026-07-16",
  "reason": "Mantenimiento del aula principal"
}
```

Resultado esperado: `201 CREATED`.

**Paso 2 - Registrar excepción de instructor (rango de varios días) sobre otro horario**

```http
POST http://localhost:8080/api/admin/schedule-exceptions
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
Content-Type: application/json

{
  "idSchedule": "{UUID_DE_OTRO_HORARIO}",
  "exceptionType": "INSTRUCTOR_CHANGE",
  "idInstructorReplacement": "{UUID_INSTRUCTOR_REEMPLAZO}",
  "exceptionDate": "2026-07-20",
  "endDate": "2026-07-24",
  "reason": "Instructor titular en incapacidad médica"
}
```

Resultado esperado: `201 CREATED`.

**Paso 3 - Consultar excepciones del horario**

```http
GET http://localhost:8080/api/admin/schedule-exceptions/schedule/{UUID_DEL_HORARIO}
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

Resultado esperado: `200 OK` con la lista de excepciones asociadas.

**Paso 4 - Intentar registrar una excepción solapada (debe fallar)**

```http
POST http://localhost:8080/api/admin/schedule-exceptions
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
Content-Type: application/json

{
  "idSchedule": "{UUID_DE_OTRO_HORARIO}",
  "exceptionType": "ENVIRONMENT_CHANGE",
  "idEnvironment": "{UUID_CUALQUIER_AMBIENTE}",
  "exceptionDate": "2026-07-22",
  "reason": "Prueba de solapamiento"
}
```

Resultado esperado: `400 Bad Request` — `"Ya existe una excepción registrada para este horario en la fecha seleccionada."` (porque el 22 de julio cae dentro del rango 20–24 registrado en el paso 2).

**Paso 5 - Eliminar excepción**

```http
DELETE http://localhost:8080/api/admin/schedule-exceptions/{UUID_DE_LA_EXCEPCION}
Authorization: Bearer TOKEN_ADMIN_O_COORDINATOR
```

Resultado esperado: `204 NO CONTENT`. La excepción queda `INACTIVE` y el horario vuelve a su configuración original.
