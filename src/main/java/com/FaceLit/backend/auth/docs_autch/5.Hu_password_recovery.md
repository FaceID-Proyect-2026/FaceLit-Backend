# HU-05 — Restablecimiento de contraseña

## ¿Qué hace HU-05?

Permite que un usuario que olvidó su contraseña pueda recuperarla mediante un código de 6 dígitos enviado a su correo registrado. El usuario ingresa el código junto con la nueva contraseña, y el sistema la actualiza de forma segura. La contraseña anterior queda invalidada automáticamente al sobreescribirse en BD.

Regla de negocio confirmada: si el correo no está registrado, el sistema **rechaza explícitamente** con "Correo no registrado" (no se usa respuesta genérica).

---

## Flujo completo

```
POST /api/auth/request-recovery { email }
        ↓
1. Busca Credential por email → si no existe, rechaza
2. Invalida el código anterior del usuario (si tenía uno activo)
3. Genera código de 6 dígitos (mismo patrón que EmailVerification)
4. Guarda PasswordRecovery con expiración de 5 minutos
5. Envía el código por correo con EmailService.sendRecoveryCode()
        ↓
Usuario revisa su correo y recibe el código
        ↓
POST /api/auth/reset-password { token, newPassword, confirmPassword }
        ↓
1. Busca el PasswordRecovery por token → si no existe, "Código incorrecto"
2. Verifica isCurrent() → si used=true o expiró, rechaza con mensaje correspondiente
3. Verifica que newPassword == confirmPassword
4. Hashea la nueva contraseña con BCrypt y actualiza Credential
5. Resetea failedAttempts a 0
6. Marca el PasswordRecovery como used = true
        ↓
Contraseña restablecida — la anterior queda inválida automáticamente
```

## Archivos creados, por capa

### 📁 Model — `auth/model/security/`

#### `PasswordRecovery.java`
Mapea la tabla `security.password_recovery`. Representa cada solicitud de recuperación de contraseña.

```
id_password_recovery → UUID, clave primaria
user                  → FK → security.user_app (ManyToOne)
token                 → String, código de 6 dígitos (el campo soporta hasta 255 chars,
                         pero se usa solo para el código corto, igual que EmailVerification)
request_date          → OffsetDateTime, momento de la solicitud
expiration_date       → OffsetDateTime, vence 5 minutos después
used                  → boolean, true cuando ya se usó (no se puede reutilizar)
state                 → Enum RecoveryState (ACTIVE/INACTIVE) — existe en el Model
                         pero NO se usa en la lógica; se controla todo con `used`
```

Método propio:
```java
isCurrent() → true si !used && OffsetDateTime.now().isBefore(expirationDate)
// Mismo patrón que isCurrent() en EmailVerification.java
```

---

### 📁 Enum — `auth/model/enums/`

#### `RecoveryState.java`
```java
ACTIVE
INACTIVE
```
Existe en el Model por la tabla SQL original, pero la lógica de negocio se maneja completamente con el campo `used` (boolean) — más simple y consistente con `EmailVerification`.

```

```

#### `ResetPasswordDTO.java`
JSON de entrada para cambiar la contraseña.
```json
{
  "token": "483920",
  "newPassword": "Nueva@123",
  "confirmPassword": "Nueva@123"
}
```
```
token           → @NotBlank @Pattern — exactamente 6 dígitos numéricos
newPassword     → @NotBlank @Pattern — 8-15 chars, mayúscula, número, símbolo
confirmPassword → @NotBlank — se compara contra newPassword en el ServiceImpl
```

### 📁 ServiceImpl — `auth/service/serviceImpl/security/`

#### `PasswordRecoveryServiceImpl.java`

**`requestRecovery()`**
```
Paso 1 → busca Credential por email → si no existe, lanza "Correo no registrado"
Paso 2 → invalida el código anterior activo del usuario (used = true)
Paso 3 → genera código de 6 dígitos con Random — igual que en RegisterServiceImpl
Paso 4 → guarda PasswordRecovery con expiración de 5 minutos
Paso 5 → envía el código por correo con emailService.sendRecoveryCode()
Paso 6 → responde con codeSent()
```

**`resetPassword()`**
```
Paso 1 → busca PasswordRecovery por token → si no existe, "Código incorrecto"
Paso 2 → verifica isCurrent() → diferencia entre "ya usado" y "vencido"
Paso 3 → verifica que newPassword == confirmPassword
Paso 4 → obtiene el User y su Credential desde la entidad PasswordRecovery
Paso 5 → hashea la nueva contraseña con passwordEncoder.encode() y actualiza Credential
         (la contraseña anterior queda inválida automáticamente al sobreescribirse)
Paso 6 → resetea failedAttempts a 0
Paso 7 → marca el PasswordRecovery como used = true
Paso 8 → responde con passwordReset()
```

## Notas importantes

- **No se tocó `SecurityConfig`** — los endpoints nuevos ya quedan cubiertos por `/api/auth/**`.
- **No se creó `UserConfiguration`** todavía — esa entidad queda pendiente para cuando se retome.
- **El campo `state` del Model `PasswordRecovery` no se usa** — toda la lógica de vigencia se maneja con `used` + `isCurrent()`, igual que `EmailVerification`.
- **La contraseña anterior se invalida automáticamente** — no se requiere lógica extra, ya que `Credential` solo guarda el hash actual; al sobreescribirlo, el anterior deja de existir en BD.
