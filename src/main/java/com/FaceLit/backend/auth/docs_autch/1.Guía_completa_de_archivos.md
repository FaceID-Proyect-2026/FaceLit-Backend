## El flujo completo de un registro

```
Frontend manda POST /api/auth/register con JSON
        ↓
RegisterController recibe el request
        ↓
@Valid valida el RegisterRequestDTO
        ↓
RegisterServiceImpl ejecuta la lógica de negocio
        ↓
UserRepository y CredentialsRepository hablan con PostgreSQL
        ↓
RegisterServiceImpl construye el RegisterResponseDTO
        ↓
RegisterController devuelve la respuesta al frontend
```

## Capa shared/ — compartida por todo el proyecto

---

### `shared/model/AuditBase.java`

**Para qué sirve:** Es la clase base que todas las entidades extienden. Contiene los campos de auditoría que se repiten en todas las tablas — así no los escribes en cada entidad.

**Qué contiene:**

| Campo | Se llena | Cuándo |
|---|---|---|
| `createdAt` | Automático | Al crear el registro |
| `updatedAt` | Automático | Al modificar el registro |
| `createdBy` | Manual | Cuando haya JWT — pendiente |
| `updatedBy` | Manual | Cuando haya JWT — pendiente |
| `deletedAt` | Manual | Al hacer soft delete |
| `deletedBy` | Manual | Al hacer soft delete |

**Anotación clave:** `@MappedSuperclass` — le dice a JPA que esta clase no genera tabla propia. Sus campos se copian a cada tabla que la extienda.

**Cómo se usa:**
```java
public class User extends AuditBase { ... }
public class Credential extends AuditBase { ... }
```

---

### `shared/exception/GlobalExceptionHandler.java`

**Para qué sirve:** Captura todos los errores que ocurren en cualquier parte del backend y los convierte en respuestas JSON legibles para el frontend. Sin esta clase, Spring devolvería errores feos con stack trace.

**Qué captura:**

| Método | Captura | Código HTTP | Cuándo ocurre |
|---|---|---|---|
| `handleValidacion` | `MethodArgumentNotValidException` | 400 | Campo vacío, email inválido, contraseña débil |
| `handleRegistro` | `RegisterException` | 409 | Email o documento duplicado |
| `handleGeneral` | `Exception` | 500 | Cualquier error inesperado |

**Anotación clave:** `@RestControllerAdvice` — le dice a Spring que intercepte todos los errores de todos los controllers.

## Capa auth/model/ — las entidades JPA

---

### `auth/model/User.java`

**Para qué sirve:** Representa la tabla `user` en PostgreSQL. Es el espejo de la tabla — cada campo de la clase es una columna en la BD.

**Campos propios:**

| Campo Java | Columna BD | Tipo | Restricción |
|---|---|---|---|
| `idUser` | `id_user` | UUID | PK, autogenerado |
| `documentNumber` | `document_number` | VARCHAR(10) | UNIQUE, NOT NULL |
| `firstName` | `first_name` | VARCHAR(50) | NOT NULL |
| `lastName` | `last_name` | VARCHAR(50) | NOT NULL |
| `birthDate` | `birth_date` | DATE | NOT NULL |
| `accountStatus` | `account_status` | VARCHAR(20) | NOT NULL |

**Campos heredados de AuditBase:** `createdAt`, `updatedAt`, `createdBy`, `updatedBy`, `deletedAt`, `deletedBy`

**Relación:** `@OneToOne(mappedBy = "user")` con `Credential` — Usuario no tiene la FK, Credential sí.

---

### `auth/model/Credential.java`

**Para qué sirve:** Representa la tabla `credential`. Guarda los datos de acceso del usuario — email y contraseña hasheada.

**Campos propios:**

| Campo Java | Columna BD | Tipo | Restricción |
|---|---|---|---|
| `idCredential` | `id_credential` | UUID | PK, autogenerado |
| `email` | `email` | VARCHAR(50) | UNIQUE, NOT NULL |
| `password` | `password_hash` | VARCHAR(255) | NOT NULL |
| `credentialStatus` | `credential_status` | VARCHAR(20) | NOT NULL |
| `failedAttempts` | `failed_attempts` | INTEGER | DEFAULT 0 |
| `user` | `id_user` | UUID | FK → user.id_user |

**Relación:** `@OneToOne @JoinColumn(name = "id_user")` — Credential tiene la FK que apunta a User.

**⚠️ Importante:** `password` guarda el hash BCrypt de 60 caracteres, nunca la contraseña original. Por eso la columna tiene `length = 255`.

---

### `auth/model/enums/AccountStatus.java`

**Para qué sirve:** Define los únicos valores válidos para el estado de la cuenta de un usuario. Evita errores de tipeo como guardar "ACTIV0" con cero.

```
ACTIVE              → cuenta activa y funcionando
INACTIVE            → cuenta desactivada
PENDING_CONSENT     → menor de edad esperando autorización del acudiente
BLOCKED             → bloqueada por demasiados intentos fallidos
```

---

### `auth/model/enums/CredentialStatus.java`

**Para qué sirve:** Define los únicos valores válidos para el estado de las credenciales.

```
ACTIVE    → credencial activa
INACTIVE  → credencial desactivada
BLOCKED   → bloqueada por intentos fallidos
```

## Capa auth/repository/ — acceso a la BD

---

### `auth/repository/UserRepository.java`

**Para qué sirve:** Es la interfaz que habla con la tabla `user` en PostgreSQL. Spring genera el SQL automáticamente leyendo el nombre de los métodos.

**Métodos:**

| Método | SQL generado | Usado en |
|---|---|---|
| `existsByDocumentNumber(String)` | `SELECT COUNT(*) FROM user WHERE document_number = ?` | RegisterServiceImpl paso 1 |
| `save(User)` | `INSERT INTO user ...` | RegisterServiceImpl paso 5.2 |
| `findById(UUID)` | `SELECT * FROM user WHERE id_user = ?` | HUs futuras |

**`extends JpaRepository<User, UUID>`** — el primer tipo es la entidad, el segundo es el tipo de la PK. Spring genera automáticamente: `save`, `findById`, `findAll`, `deleteById`, `existsById`.

---

### `auth/repository/CredentialsRepository.java`

**Para qué sirve:** Habla con la tabla `credential`.

**Métodos:**

| Método | SQL generado | Usado en |
|---|---|---|
| `existsByEmail(String)` | `SELECT COUNT(*) FROM credential WHERE email = ?` | RegisterServiceImpl paso 2 |
| `findByEmail(String)` | `SELECT * FROM credential WHERE email = ?` | Login — HU futura |
| `save(Credential)` | `INSERT INTO credential ...` | RegisterServiceImpl paso 5.4 |

**`Optional<Credential> findByEmail`** — usa `Optional` porque el email es UNIQUE, máximo puede existir uno o ninguno. Obliga a manejar el caso de que no exista.

## Capa auth/dto/ — objetos de transferencia de datos

---

### `auth/dto/request/RegisterRequestDTO.java`

**Para qué sirve:** Define exactamente qué datos debe mandar el frontend para registrarse. Tiene las validaciones de formato — si algo falla, Spring devuelve 400 automáticamente sin llegar al Service.

**Campos y validaciones:**

| Campo | Validación | Error si falla |
|---|---|---|
| `firstName` | Solo letras, max 50 | "El nombre es obligatorio" / "El nombre solo puede contener letras" |
| `lastName` | Solo letras, max 50 | "El apellido es obligatorio" / "El apellido solo puede contener letras" |
| `documentNumber` | Solo números, max 10 | "El número de documento es obligatorio" |
| `email` | Formato email, max 50 | "El email es obligatorio" / "El email no es válido" |
| `password` | 8-15 chars, mayúscula, número, símbolo | "La contraseña debe tener entre 8 y 15 caracteres..." |
| `birthDate` | NotNull + @ValidBirthDate (8-100 años) | "La fecha de nacimiento es obligatoria" |

**¿Por qué no tiene `@NoArgsConstructor`?** Jackson (el convertidor de JSON a Java) usa los setters para llenar los campos. Con `@Getter` y `@Setter` es suficiente.

---

### `auth/dto/response/RegisterResponseDTO.java`

**Para qué sirve:** Define qué devuelve el backend al frontend después de procesar el registro.

**Campos:**

| Campo | Tipo | Descripción |
|---|---|---|
| `message` | String | Texto legible del resultado |
| `status` | String | Código para que el frontend sepa qué pantalla mostrar |
| `requiresConsent` | boolean | true si es menor de edad |
| `id_user` | UUID | ID del usuario — null si es menor de edad |

**Métodos de fábrica:**

```
majorAge(UUID id) → "REGISTERED", requiresConsent=false, id del usuario
minorAge()        → "PENDING_CONSENT", requiresConsent=true, id=null
```

**JSON que recibe el frontend:**

Mayor de edad:
```json
{
  "message": null,
  "status": "REGISTERED",
  "requiresConsent": false,
  "id_user": "uuid-aqui"
}
```

Menor de edad:
```json
{
  "message": null,
  "status": "PENDING_CONSENT",
  "requiresConsent": true,
  "id_user": null
}
```

---

### `auth/dto/validation/ValidBirthDate.java`

**Para qué sirve:** Es una anotación personalizada que se pone sobre el campo `birthDate` en el RequestDTO. Le dice a Spring que use `BirthDateValidator` para validar ese campo.

**¿Por qué se necesita?** Las anotaciones estándar como `@Past` solo validan que la fecha sea en el pasado. No pueden verificar que la edad esté entre 8 y 100 años — eso requiere cálculo.

**Las tres líneas obligatorias:**
```java
String message() default "...";  // mensaje por defecto
Class<?>[] groups() default {};   // OBLIGATORIO por Jakarta — no se puede quitar
Class<? extends Payload>[] payload() default {};  // OBLIGATORIO por Jakarta — no se puede quitar
```
`groups` y `payload` los exige el framework. Sin ellos el proyecto no compila.

---

### `auth/dto/validation/BirthDateValidator.java`

**Para qué sirve:** Contiene la lógica real de validación de la fecha. Es quien hace el cálculo de la edad.

**Lógica:**
```
Si birthDate es null → deja pasar (@NotNull lo maneja)
Si age < 8  → error "El usuario debe tener al menos 8 años"
Si age > 100 → error "La fecha de nacimiento no es válida"
Si está entre 8 y 100 → válido ✅
```

## Capa auth/exception/

---

### `auth/exception/RegisterException.java`

**Para qué sirve:** Es la excepción personalizada del módulo de registro. Se lanza cuando algo sale mal en la lógica de negocio — email duplicado, documento duplicado.

**Por qué extiende `RuntimeException`:** No obliga a usar `try/catch` en todos lados. El `GlobalExceptionHandler` la captura automáticamente y devuelve 409 al frontend.

**Cómo se usa en el ServiceImpl:**
```java
throw new RegisterException("El email ya está registrado");
// La ejecución se detiene aquí
// GlobalExceptionHandler la captura y manda 409 al frontend
```

## Capa auth/service/

---

### `auth/service/RegisterService.java`

**Para qué sirve:** Es la interfaz — define el contrato. Dice qué métodos debe tener el Service sin implementar la lógica.

**Por qué existe separada del Impl:** El Controller apunta a la interfaz, no a la implementación. Si en el futuro cambias cómo funciona el registro, el Controller no se entera ni le importa.

```java
public interface RegisterService {
    RegisterResponseDTO register(RegisterRequestDTO dto);
}
```

---

### `auth/service/impl/RegisterServiceImpl.java`

**Para qué sirve:** Aquí vive toda la lógica de negocio del registro. Es quien toma todas las decisiones.

**Lógica paso a paso:**

```
1. ¿El documento ya existe en BD?    → Si sí: RegisterException
2. ¿El email ya existe en BD?        → Si sí: RegisterException
3. Calcular edad con Period.between()
4. ¿Tiene menos de 18 años?         → Si sí: retornar minorAge() sin guardar nada
5. Construir objeto User con los datos del DTO
6. Guardar User en BD → obtener el UUID generado
7. Construir objeto Credential
8. Hashear contraseña con BCrypt
9. Asociar Credential con el User guardado
10. Guardar Credential en BD
11. Retornar majorAge(uuid del usuario)
```

**`@Transactional`:** Si el paso 9 falla, el paso 6 se revierte. La BD queda limpia.

## Capa auth/controller/

---

### `auth/controller/RegisterController.java`

**Para qué sirve:** Es la puerta de entrada del módulo. Recibe el request HTTP del frontend, valida el formato con `@Valid`, llama al Service y devuelve la respuesta.

**Endpoint:**

| Método | URL | Acceso | Body |
|---|---|---|---|
| POST | `/api/auth/register` | Público | `RegisterRequestDTO` en JSON |

**Códigos de respuesta:**

| Código | Cuándo |
|---|---|
| 201 Created | Registro exitoso — mayor de edad |
| 202 Accepted | Menor de edad — pendiente de consentimiento |
| 400 Bad Request | Validación fallida — campo vacío, formato inválido |
| 409 Conflict | Email o documento ya registrado |
| 500 Internal Server Error | Error inesperado |

**Regla:** El controller no tiene lógica. Solo recibe, valida formato y delega al Service.

## Capa config/

---

### `config/SecurityConfig.java`

**Para qué sirve:** Configura Spring Security — define qué endpoints son públicos y cuáles requieren autenticación. También define el `PasswordEncoder` que usa el ServiceImpl.

**Configuración actual:**

```
/api/auth/** → público (registro y login no necesitan token)
Todo lo demás → requiere autenticación
```

**`PasswordEncoder`:** Bean de BCrypt con factor 10. Se inyecta automáticamente en `RegisterServiceImpl`. Factor 10 es el estándar recomendado para producción.

**`SessionCreationPolicy.STATELESS`:** Spring no crea sesiones. Cada request se autentica con el JWT. Obligatorio cuando se usa JWT.

**`csrf.disable()`:** CSRF es protección para formularios HTML. En APIs REST con JWT no se necesita.
